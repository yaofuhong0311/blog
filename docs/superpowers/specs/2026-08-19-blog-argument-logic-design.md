# 博客论证逻辑重构设计

## 背景

上一轮编辑已经让技术文章具备摘要层和证据层，但部分“快速阅读”只是从原文提取章节，没有解决以下问题：

- 同一篇文章同时回答多个问题，中心判断不稳定。
- 背景、机制、源码和个人选择并列出现，缺少因果关系。
- 摘要复述目录，读者仍需要阅读全文才能理解作者结论。
- 折叠层保留了重复和偏题内容，篇幅缩短主要依赖隐藏，而不是编辑。

本轮允许直接删除重复、偏题和不能支撑中心判断的内容，不以完整保留原稿为目标。

## 目标

让每篇文章形成一条可以复述的论证链：

```text
问题
→ 核心判断
→ 判断依据
→ 工程选择或理解
→ 适用边界
```

读者应能在首屏判断文章是否值得继续阅读，并在读完后明确知道作者表达了什么、依据是什么、结论在什么条件下成立。

## 文章类型与结构

### 源码调研

```text
要验证的问题
→ 关键源码路径
→ 机制如何成立
→ 对设计的判断
→ 未覆盖的边界
```

- 代码片段只保留证明关键机制所需的最小范围。
- 文件清单、完整调用链和旁支机制放入“实现依据”。
- 不把“阅读了哪些文件”当作文章结论。

### 工程实践

```text
实际问题
→ 根因判断
→ 候选方案与取舍
→ 当前实现
→ 效果、代价和调整条件
```

- 重点解释为什么这样做，而不是罗列实现步骤。
- 无法验证的效果不写成确定结论。
- 配置和操作过程只在影响判断时保留。

### 学习笔记与系统机制

```text
核心问题
→ 必要概念
→ 概念之间的关系
→ 我的理解
→ 适用范围或常见误区
```

- 术语只在推导需要时引入。
- 不按原始学习顺序组织文章。
- 已在其他文章完整解释的机制使用站内链接承接。

### 工具与工作流

```text
解决的问题
→ 使用方式
→ 关键设计取舍
→ 适合与不适合的场景
```

- 功能清单从属于使用目标。
- 没有截图的工具优先用流程图说明输入、处理和输出。
- 不用假设性的规模、收益或用户反馈填充内容。

## 编辑规则

1. 每篇只保留一个中心判断；无法服务该判断的段落删除或迁移。
2. 开头使用一段话表达问题、判断和阅读收益，不同时设置“结论先行”和重复摘要。
3. “快速阅读”不再复述章节目录，只保留三个能够独立成立的判断。
4. 相邻章节必须存在递进、因果、对比或从事实到选择的关系。
5. 重复定义、重复结论、过程性记录和无关扩展直接删除，不再依赖折叠隐藏。
6. `<details>` 只承接源码、配置、完整表格和边界枚举，不承接主论证。
7. 个人意见必须说明依据、代价和改变选择的触发条件。
8. 标题、description、开头和结语应回答同一个问题。

## 执行顺序

按专题逐组处理，避免同时修改全部文章后才发现标准不合适：

1. Agent 工程
2. 源码调研
3. 沙箱系统与工程实践
4. AI Coding、工具与其他内容

每组先人工重写一篇并核对论证链，再处理同组其余文章。每篇独立提交，保留可审查的 Git 历史。

## 验收

- 能用一句话复述每篇文章的问题和核心判断。
- 开头、主体与结语不存在相互偏离的主题。
- 主论证不依赖展开 `<details>` 才能成立。
- “快速阅读”中的每一点都在正文中得到论证。
- 没有重复定义、重复结论或仅记录调研过程的段落。
- 事实、推断和个人选择能够明确区分。
- 站内链接、图片、移动端布局和现有构建检查继续通过。
