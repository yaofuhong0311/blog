# 博客摘要优先编辑系统设计

## 背景

当前博客共 45 篇文章，中位长度约 3379 个正文字符，39 篇超过 2500 字，平均每篇包含 6.5 个二级章节。文章普遍保留了完整调研过程，但问题、结论、推导和证据处于同一阅读层，导致中心观点出现较晚。

## 目标

建立“摘要优先、证据按需展开”的统一文章结构，使读者在首屏内理解文章解决的问题、作者结论和继续阅读的收益，同时保留源码证据与工程边界。

## 编辑合同

1. 每篇文章只表达一个中心判断。
2. 标题、description 和开头使用同一问题表达。
3. 开头 220 个正文字符内出现问题、结论和阅读收益。
4. 普通可见正文目标为 1500～2200 个中文字符。
5. 主体二级章节不超过 4 个，不计“实现依据”和“参考资料”。
6. 细节通过表格、站内链接或 `<details>` 证据层承接。
7. 不为了缩短篇幅删除事实来源、适用边界和个人工程判断。
8. 每篇最多保留一张直接支撑中心判断的主图；第二张图必须提供独立信息，否则删除。
9. 不新增文章分类、依赖或独立页面。

## 标准结构

```text
问题 + 结论 + 阅读收益
→ 核心图或结论卡片（可选）
→ 关键判断一
→ 关键判断二
→ 我的选择 / 如何落地
→ 实现依据（源码调研按需展开）
→ 参考资料
```

## 验收

- 五篇文章均能在开头 220 个正文字符内表达问题与结论。
- 每篇主体二级章节不超过 4 个。
- 桌面端和 390px 移动端无页面级横向溢出。
- 现有图片与站内链接均可访问。
- `pnpm exec biome check ./src`、`pnpm check`、`pnpm build` 通过。
- 样板经人工阅读确认后，才对剩余文章进行批量改造。
