# Agent Sandbox 工程实践专题设计

## 目标

将飞书文档中的 Sandbox 平台学习与工程实践整理为独立专题，回答以下问题：

- 控制面如何判断任务状态与运行环境是否一致。
- Sandbox 消失后，何时可以恢复，何时必须失败。
- 单个动作如何借助幂等键、动作标识和 Checkpoint 安全恢复。
- 隔离方案与冷启动优化如何影响平台设计。

专题面向具有后端、Kubernetes 或 Agent 平台基础的读者。文章需要同时提供直观问题、机制解释、工程边界和可迁移的设计判断。

## 与现有系列的边界

现有“沙箱底层机制”侧重隔离、存储、网络、调度和运行时原理。本专题侧重控制面如何组合这些机制，形成可恢复、可运营的 Agent Sandbox 平台。

容器、gVisor、MicroVM、CoW 和 Snapshot 只作为工程决策所需的背景，不重复展开已经发布的基础原理。需要进一步解释时，通过站内链接引用现有文章。

## 专题结构

### 第一篇：为什么控制面需要状态收敛

- 区分期望状态、观测状态和业务状态。
- 解释请求链式执行与 Reconcile 的差异。
- 讨论 Sandbox 消失后为什么不能直接创建新 Pod 继续旧任务。
- 给出可安全重做、不可安全重做和无法判断三类恢复决策。
- 明确文件持久化不等于进程现场或动作状态仍然存在。

### 第二篇：一次动作如何在故障后安全恢复

- 区分动作状态、幂等键、动作标识和任务 Checkpoint。
- 说明幂等记录必须先于外部动作建立。
- 分析网络断开、结果丢失、服务重启和多副本路由。
- 结合异步命令执行说明提交、查询和恢复接口的职责。

配图：动作提交时序图和状态机。

### 第三篇：系统调用最先由谁处理

- 用“第一个处理系统调用的受信任组件”比较普通容器、gVisor 和 MicroVM。
- 说明 Namespace、cgroup、Capability、seccomp 的职责边界。
- 区分 Guest root、节点 root 和集群控制权限。
- 保留当前工程能够确认的事实，并明确无法从仓库判断的运行时配置。

配图：三条系统调用路径对比图。

### 第四篇：CoW、Snapshot 与 Warm Pool 如何降低冷启动

- 区分共享基线、保存运行状态和提前准备实例。
- 区分运行时 Snapshot、任务 Checkpoint 和 Workspace 持久化。
- 讨论预热实例的规格匹配、动态挂载限制和跨租户残留风险。
- 给出冷启动、Snapshot 恢复和 Warm Pool 分配的选择流程。

## 写作规范

- 使用正式、准确的技术表达，不使用俗语。
- 每篇从一个可观察的工程问题开始，再进入机制与实现。
- 区分“通用机制”“当前工程事实”“基于现有证据无法确认的部分”。
- 每篇给出个人工程判断，明确当前选择、选择原因、代价和升级触发条件。
- 不公开内部服务名、私有仓库路径、提交哈希、部署参数或组织信息。
- 不将未经验证的生产配置写成确定事实。
- 源码片段只保留解释边界所需的最小部分，并优先使用公开规范或开源实现作为外部引用。
