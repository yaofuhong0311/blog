需求是这样的：agent 跑到第 12 步，需要**同时试 8 种不同的下一步**，看哪个得分更高。这在训练场景里叫多轨迹采样或树搜索，而在线沙箱服务基本不涉及——用户不会要求"把我的会话分叉成 8 份"。

[第二篇](/posts/sandbox-page-fault/)讲过写时复制，这一篇补的是它**在整机粒度上的形态与代价模型**。

## 一、先对齐概念：这个词的老家

**"写时复制"这个词就来自 Unix 的 `fork()`。** 父进程调用一次，得到一个内存内容、执行位置、打开文件全都相同的子进程；早期实现真的复制整份内存，后来改成：不复制，父子页表指向同一批物理页并全部标记只读，谁写谁分家。

但整机分叉和它有一处关键差别：

|  | 复制的是 | 子体从哪继续 | **子体知不知道自己是子体** |
|---|---|---|---|
| `fork()` | 一个进程：内存 + 寄存器 + 文件描述符表 | 调用那行的下一条 | ✅ **知道**（返回值为 0） |
| **整机分叉** | **整台机器**：guest 内存 + 寄存器 + 设备状态 + 磁盘 | 被分叉那一瞬的下一条指令 | ❌ **完全不知道** |

**最后一列是后面所有坑的根源。** guest 感知时间流逝的唯一方式是执行指令，而分叉期间它一条指令都没执行——所以它连"我被暂停过"都无从察觉，更没有一个类似 `fork()` 返回值的信号可以据以善后。

## 二、机制：复制的是页表，不是数据

理解这一节只需要三个关于页表的要点：**表很小而表指向的数据很大**；**表的每一行带一个"能不能写"的开关**；**写一个标着不能写的地址，CPU 当场抛异常并把控制权交给内核**。

先记这个画面：

> 图书馆有**一本书**（快照），8 个人都要"自己的一本"。笨办法是复印 8 份。聪明办法是——8 人**共读这一本，谁都不许在原书上写字**，每人发一张**目录卡**写着"我要看第 N 页 → 去看原书第 N 页"。某人要改第 37 页时，管理员拦下、单独复印那一页给他、把他的目录卡改成"第 37 页 → 看我自己那张"。
>
> 结果：**他看第 37 页看自己的、看其余 999 页仍看原书，另外 7 人的目录卡一个字未动，全场只多用了 1 张纸。**

对应关系：

| 比喻 | 真实对象 |
|---|---|
| 原书 | 快照文件（宿主内存里躺着一份） |
| 目录卡 | **页表** |
| "不许写字" | 页表行上的只读标记 |
| 管理员拦住 | **CPU 抛写保护异常**（硬件拦截，不是代码判断） |
| 复印一页 | 内核复制那 4KB |
| 改目录卡那一行 | 改页表那一行的指向与读写位 |

所以**分叉那一刻**：给每个 VM 建一套页表，全部指向同一份数据、全部标只读——**数据一个字节都没有复制**，那一百多毫秒花在建页表上。**写的时候**：CPU 拦下 → 内核复制那 4KB → 改这个 VM 的页表那一行 → 恢复执行那条写指令，**guest 全程无感**。

有一个容易漏掉的动作值得点出：**只读标记是分叉这一步加上去的。** 这些页在快照里本来是可写的（guest 的堆栈、变量）。没有这一步，CPU 就不会在写入时抛异常，也就没有任何人知道该分家——**整套机制的触发器就是这个标记。**

## 三、代价模型：分叉是免费的，脏页才是账单

**分叉那一刻脏页为零**，内存仍然只有一份；脏页是分叉之后运行过程中逐渐产生的。因此成本与"分了几份"关系很小，与"**分叉之后各自写了多少**"成正比：

| 分叉后各自的行为 | 脏页 | 实际内存（以 8 份为例） |
|---|---|---|
| 立刻结束，什么都没写 | 0 | **1 份** |
| 各写了约 10% | 少 | 约 1.8 份 |
| 各自把所有页都写过一遍 | 全部 | **8 份——退化成完整复制，写时复制等于白做** |

由此得到一条容易说错的判据：**"分叉之后跑得短"这个说法不准确，真正的判据是"新写入量小"。**

时间只是代理指标：跑几分钟但全在**读**（比如跑一遍单元测试）依然便宜，因为读不产生脏页；只花几十秒但**加载一个 3GB 模型进内存**则会把共享优势完全消耗掉。

**推论：分叉点应当尽量靠后。** 装依赖、拉仓库、初始化这些写入量大的动作全部放在分叉之前完成，让它们进入共享的那一份，分叉之后只剩轻量试探。**分叉点越晚，共享越多，越便宜。**

## 四、它不是新机制

```text
恢复 1 份 = 映射快照文件一次，建一套页表
分叉 N 份 = 映射同一个快照文件 N 次，建 N 套页表

从运行中的 VM 分叉 = ① 先给当前状态打快照
                    ② 从这个快照恢复 N 次（可并行）
```

**不需要把它当作独立机制记忆**——它等于"快照 + 恢复"，而这两者[第二篇](/posts/sandbox-page-fault/)与[上一篇](/posts/sandbox-agentenv-case/)已经分别讲过。

## 五、guest 不知道自己被分叉的后果

回到第一节那个差别。因为 guest 拿不到任何"你是副本"的信号，一批问题会同时出现：

| 问题 | 根因 |
|---|---|
| 随机数种子相同 | 熵池在快照那一刻的状态被复制了 N 份。**加密场景下这是安全漏洞** |
| 网卡地址、IP 冲突 | 网卡配置同样在那份内存里 |
| 已建立的 TCP 连接 | N 个 guest 都认为自己持有该连接，而对端只认一个 |
| 机器标识、进程内缓存的各类唯一 ID | 全在内存里，全部相同 |

**与 `fork()` 的对照说明了善后为什么必须从外部做**：`fork()` 的子进程知道自己是子进程，可以主动重新播种、重开连接；**整机分叉的 guest 没有这个信号**，所以重新灌熵、重新分配网络身份只能由平台在分叉之后从外面执行。

这也划出了它的适用边界：**训练场景能容忍这些坑**（分支跑完即弃、不建长连接、不做加密操作）；**通用沙箱服务一个都躲不掉**——这是该机制不能直接照搬到在线服务的主要原因。

## 六、收口：同一个模式在三个层次各实现了一遍

把这一篇和[镜像那篇](/posts/sandbox-image-layering/)、[上一篇](/posts/sandbox-agentenv-case/)合起来看，会发现同一个模式出现了三次：

|  | 底（只读共享） | 上（可写增量） | 分家单位 | **谁拦住写操作** |
|---|---|---|---|---|
| overlayfs | 下层目录 | 上层目录 | **整个文件** | 内核文件系统层（**代码**） |
| overlaybd | 只读块层 | 增量块层 | 扇区 | 用户态进程（**代码**） |
| 内存写时复制 | 快照页（干净页） | 私有页（脏页） | 4KB 页 | **CPU 写保护异常（硬件）** |

但**有两个差别不要因为模式相同就抹平**：

**① 拦截者不同。** 前两行是代码在判断"这是写操作、该分家了"，第三行是 CPU 电路当场拦下。**没被写的时候第三行完全不需要任何代码参与**——这是内存共享能做到近乎零开销的原因；而块层那行每次请求都要真跑一遍用户态代码。

**② 粒度不同。** overlayfs 改一个 1GB 文件里的 1 个字节会**复制整个 1GB 文件**（[第七篇](/posts/sandbox-storage-warmpool/)讲过这个写放大）；块层与页层的单位本就是固定小块，天然没有这个问题——**这是"下沉到块层"除了能给虚拟机当硬盘之外，顺手拿到的第二个好处。**

一句话收口：**"双层结构 + 写时复制"是模式；"目录 / 扇区 / 脏页"是这个模式在三层上的不同外衣。越往下，粒度越细、拦截越便宜。**

而更上位还有一层手法，这三者其实共享：**先建立一个"假装已经有了"的映射，等真正碰到它时再付出代价**——镜像懒加载和快照懒加载是"读到才拉"，整机分叉是"写到才分家"。**49 毫秒的启动、免下载的镜像、一百多毫秒的分叉，是同一招用在三个位置。**
